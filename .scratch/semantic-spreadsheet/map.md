# Semantic Spreadsheet — wayfinder map

**Label:** `wayfinder:map`
**Status:** open

## Destination

A refined, build-ready **product spec** at `.scratch/semantic-spreadsheet/spec.md` that supersedes `handoff.md`, scoped to one coherent vertical slice: auth → CSV upload/parse → dataset storage → spreadsheet/table UI → Yes/No AI column → Jev evaluation service → 10-row preview → async full run → confidence display → uncertain-row review → CSV export.

It describes the app on the base actually chosen: `~/code/scaffold`'s stack — TanStack Start + Vite + React 19, Tailwind v4, Effect 4 (RC) on `@effect/sql-pg` with raw SQL and Effect Schema, better-auth, Effect `PersistedQueue`, S3-compatible object storage. The spec pins *product truth* — screens, data-model semantics, failure behaviour — and leaves only the **grid library** and the **hosting target** open, as named constraints.

- **Skills every session should consult:** `grilling` + `domain-modeling` for decision tickets; `research` for research tickets.
- **Standing constraints:**
  - Jev performs per-row semantic evaluation. A general-purpose LLM is never the default row evaluator.
  - The LLM's only in-scope role is pre-evaluation rule clarification. Post-hoc "Explain result" is out of scope.
  - Confidence is preserved as a real numeric value internally and never flattened into false certainty.
  - Usage is counted, not billed: rows × columns is the unit of account.
  - **No ORM.** Raw SQL through `@effect/sql-pg`, rows decoded via Effect `Schema`, never cast.
  - **better-auth owns user and session**; the app owns its own `User` row and isolation never keys off email.
  - **`PersistedQueue` runs background work** — at-least-once, no backoff, no scheduling, no dead-letter, strict FIFO per queue name.
  - **Redis is infrastructure** — added for `RateLimiter` state, which otherwise has only a process-local memory store. Rate-limit learning is shared across processes, not split between the web app and the worker.
  - Refer to tickets by name, never by bare number.

## Decisions so far

- [The real Jev / TypeSafe evaluation API](issues/01-research-jev-api.md): Jev is real — TypeSafe AI's System One model, early access from 15 Sep 2026. `POST /v1/systemone` sends one `state` plus a map of typed `questions` (Choice / Score / Noul). Choice and Score return a full distribution plus a `confidence` derived from its shape; Noul returns a bare probability and **no confidence field**. $0.042/M input tokens, output free. There is **no dataset-upload primitive** — batching is our orchestration. Rate limits and idempotency undocumented; calibration asserted but not published.
- [Hosted auth options for this stack](issues/02-research-hosted-auth.md): every realistic hosted vendor clears MVP scale. *(Superseded by **Adopt the scaffold as the project base** — better-auth was chosen, but the vendor-independent finding holds: the app owns its `User` row and isolation never keys off email.)*
- [Background-job architecture and hosting target](issues/03-research-job-architecture.md): a genuine menu of runner families with no winner chosen. *(Superseded by **Adopt the scaffold as the project base** — Effect's `PersistedQueue` was chosen instead, but the constraint stands: a single Vercel Function caps at 300s/800s, so long-lived workers rule out a serverless-only deployment.)*
- [Adopt the scaffold as the project base](issues/15-adopt-scaffold-base.md): base is the scaffold copied without history into this repo. Stack is TanStack Start + Vite + React 19 + Tailwind v4 + Effect 4 on `@effect/sql-pg`, **no ORM**, on a pnpm/Turbo monorepo. `handoff.md`'s stack section is superseded. `notes`/`documents`/`notifications` deleted; the custom jobs queue replaced by Effect `PersistedQueue`; auth is better-auth 1.7.4 following `~/code/platform`. Spec lives beside this map.
- [What confidence means](issues/04-confidence-model.md): confidence is the **winner's share of Jev's distribution**, computed by us, with Jev's own `confidence` also stored for later comparison. Yes/No is a **two-option Choice**, erasing the Noul confidence hole. Four states with four user actions — high confidence, needs review (below a **per-column threshold, default 0.8, editable now**), **unable to determine** (an *input* state, detected by a second Noul sufficiency question, whose judgment is discarded), and failed. The spec may **not** claim calibration — confidence is a relative signal only, and the real number is always preserved internally.
- [One result shape across the three column types](issues/05-result-shape.md): **one shape** for all three types — a **label set** (name + description per label, plus an `ordered` flag, plus a rendering-only type tag); Yes/No is two fixed labels, Category N unordered, Score N ordered. A Score's stored value is the **argmax level label**, with Jev's fractional score kept as a detail. A result stores the distribution, our computed confidence, Jev's raw confidence, the four-value status, and a **trimmed** provider response on **every** row. Rows live in Postgres as `jsonb` **and** the original uploaded file is archived. **Evaluation is a unit of account, not an entity.** Vocabulary: AI column, Result, Status, Correction.
- [Preview semantics](issues/06-preview-semantics.md): preview takes a **spread evenly through the sheet**, default **10 rows, adjustable 5–50**. It writes **real Results** alongside the AI column; abandoning the drawer deletes both, so no half-evaluated columns exist. Promotion **reuses** the previewed rows and evaluates only the rest. Re-previewing **recomputes every row** — no caching. Preview is the **same pipeline** as the full run, bounded. A failing row never blocks promotion.
- [Corrections layered over model output](issues/07-corrections-model.md): a correction is **its own record anchored to the *(AI column, row)* pair**, never to a result — so human judgment outlives any re-run. One **effective value** everywhere (correction if present, else the model's), with the model's raw value read only in row detail. Corrections **survive re-runs even after a rule edit**, and corrected cells stay visibly marked. **Two honest numbers**: the run summary reports the model's counts and never changes; the review queue shows *still-to-review* and shrinks. Corrections are constrained to the column's label set, and rows the model couldn't judge are correctable.
- [Batch-run semantics](issues/08-batch-run-semantics.md): **one queue item per *(row, AI column)***, with an Effect `RequestResolver` in the adapter doing any batching. Retries split into **retryable** (`429`/`529`/timeout → backoff honouring `Retry-After`, then fail) and **terminal** (`422`/bad criteria → write a failed Result and succeed, burning no attempt), with a persisted **adaptive `RateLimiter` in front** that *learns* Jev's undocumented limit. **Fairness: one queue per user, round-robin claims, plus reserved slots for interactive work** — `PersistedQueue` is strict FIFO per `queue_name` and would otherwise let a bulk run block a preview. **Redis added** for limiter state. Preview goes **through the queue too**. Cancel is a flag on the run. Progress is **derived from the results table** and polled. `completed` means every row reached a terminal state, and the summary reports the four status counts separately. Usage is evaluations, with a dollar estimate only after a preview has measured tokens.
- [Export shape for the slice](issues/09-export-shape.md): original columns **verbatim and in original order**, then per AI column in creation order its **value** and its **confidence** — confidence **on by default**, one toggle. Non-answered rows write **`Unable to determine`** / **`Failed`** into the value cell with a blank confidence, so the export explains itself with no third column (the value column therefore mixes labels with two status words — accepted). Confidence is a **plain decimal** (`0.72`), never a percentage string. Export carries the **effective value only**, never the model's overridden one. **All rows, original order, regardless of filters** — flagged as the most likely thing to revisit. RFC 4180 CSV, no provenance columns.
- [Dataset privacy and lifecycle](issues/10-dataset-privacy-lifecycle.md): isolation is a **foreign key to better-auth's `user.id`** plus session-scoped queries — which means **auth migrations must run first**, inverting the order inherited from `~/code/platform`. Object keys encode **user and dataset**; on delete the DB records go **immediately** while the object deletion is **enqueued and retried**. Ingest limits **50 MB / 100,000 rows / 256 columns** (down from the inherited 5 GiB), with messages naming the limit and the actual value. Encoding is **detected and transcoded** from Windows-1252 rather than rejected, and the assumption is stated. Jev receives the **whole row**, disclosed. Logs carry **identifiers and metrics only** — never cell values or instruction text. Deletion is **hard and immediate**, object included; only an aggregate usage count survives, with nothing else retained.
- [Table behaviour in the slice](issues/11-table-behaviour.md): grid is **TanStack Table + TanStack Virtual** — headless, continuous scrolling, no pagination (this names the last open choice in the destination). All six listed behaviours are in. **Score columns sort by level order**, not alphabetically. Filter-by-confidence means the **four status buckets**, never a slider; filters are **AND across columns, OR within one**, and **live in the URL**. Cells show value + percentage + ⚠, and clicking opens a **row-detail panel** (no explain button). AI columns get a tinted header and a single vertical rule; a corrected cell carries a **persistent** edited marker. *(human-ratified)*
- [Demo dataset and sample rule](issues/12-demo-dataset.md): 20 fictional companies on `company / description / employee_count / country`, a **third of them deliberately ambiguous** so the demo produces real "needs review" rows and teaches the confidence model. Sample rule `B2B SaaS?`. Created **on demand**, not seeded at signup, and evaluated **live**, never pre-computed. An ordinary dataset in every other respect. *⚠️ provisional — agent-decided, not human-ratified*
- [Rule clarification](issues/13-rule-clarification.md): fires only on an explicit **"Improve this"**, never automatically; produces a rewritten instruction the user must accept, with the original recoverable; an unaccepted suggestion is **never used**. Example questions are drawn from the dataset's own headers. Failure is silent and the path is **feature-flagged** off without a provider key. **Never evaluates a row**, and uses a general-purpose LLM, never Jev. *⚠️ provisional — agent-decided, not human-ratified*
- [The evaluation-service boundary](issues/14-evaluation-service-boundary.md): `evaluate({ rows, aiColumn })` takes **row content, never a row id** — the requirement the deferred connector effort depends on. **Two questions per call**, judgment plus Noul sufficiency. **API shapes verified live, not inferred:** `choice` takes `criteria` as a **label → description map** (passing `options` returns 422), `score` takes **an ordered array** and returns the weighted index, `noul` returns no confidence. Batching via an Effect `RequestResolver`; a `RateLimiter` wraps every call with adaptive feedback. `422`/`401` terminal, `429`/`529`/5xx retryable; **provider errors translated before logging**. Trimmed response stored per row. **No mock — the live integration works.** *⚠️ provisional — agent-decided, not human-ratified*

## Out of scope

- **XLSX import and export** — CSV proves the loop; XLSX is convenience past the destination.
- **Saved rules / reusable rule library** — reuse is a second-dataset concern; the slice proves the first.
- **Template gallery** — pre-filled rule definitions are content, not the core loop.
- **Stripe, paid plans, evaluation limits and quotas** — billing is explicitly deferred by the brief.
- **SSO, RBAC, team administration, shared workspaces** — note better-auth ships an `organization` plugin, so this is a deliberate *not now*, not a technical absence.
- **Google Sheets and Airtable integrations; public API.**
- **Live collaborative spreadsheet editing.**
- **Chat-first interfaces; workflow builders; autonomous web research.**
- **Microservices.**
- **Visual polish pass.**
- **LLM "Explain result"** — post-hoc explanation is out; pre-evaluation rule clarification is in.
- **[Sync AI columns with live Google Sheets and Airtable](issues/17-sync-with-live-sheets.md)** — a connector-driven, event-driven product was considered as a redraw of this destination and **deliberately deferred**. It is a separate future effort with its own destination, not a resumption of this map; the brief excludes Sheets and Airtable from v1 for reasons that still hold. This effort owes it exactly one thing, recorded on **The evaluation-service boundary**: the evaluator must stay connector-agnostic. That ticket's body holds the four decisions already settled for it.
